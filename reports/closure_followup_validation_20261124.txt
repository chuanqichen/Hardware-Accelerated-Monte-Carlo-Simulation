  Approach for a future PR that commits build products, without rewriting the
  contributor's branch:
    1. Prefer that the author removes them from their own branch, as here.
    2. Otherwise add one removal commit on top and use GitHub's squash merge.
       Main then gains one commit whose tree has no products, and no product
       blob becomes reachable from main. A merge commit or a rebase merge would
       carry the commits that add them into main's history.
    3. If the branch cannot take a removal commit, open a replacement PR with a
       single commit holding the final tree without the products, credit the
       author and close the original.
    4. For a stacked branch, rebase only your own branch onto the new lower
       head (git rebase --onto <new-head> <old-head> <branch>), and never push
       a branch that still contains the replaced head.
    5. Before merging, scan the whole range as well as the tip:
         git log --diff-filter=A --name-only --format= <base>..<head> \
           | grep -E '(^|/)(simv|simv\.daidir|csrc)(/|$)|ucli\.key$|vc_hdrs\.h$|AN\.DB'
